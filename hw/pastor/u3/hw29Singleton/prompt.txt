Actúa como un Arquitecto de Software Senior, especialista en Patrones de Diseño (GoF), Arquitectura MVC estricta, Clean Code y Java Enterprise con MongoDB.

CONTEXTO DEL PROYECTO
Estoy desarrollando un Sistema de Gestión de Ventas e Inventarios en Java (Maven) que utiliza MongoDB (NoSQL) como base de datos. Necesito implementar una nueva funcionalidad llamada Sistema de Alertas de Stock, respetando principios de alta cohesión, bajo acoplamiento y separación estricta de responsabilidades.

REQUERIMIENTOS TÉCNICOS (OBLIGATORIOS)

Patrón de Diseño – Singleton (AlarmConfig)

Crear una clase llamada AlarmConfig dentro del paquete Config.

Implementar correctamente el patrón Singleton:

Constructor privado

Atributo private static AlarmConfig instance

Método público getInstance()

Atributos:

private int minimumStock

Persistencia:

El valor de minimumStock debe almacenarse y recuperarse desde MongoDB.

Colección: sales_configuration

El documento representa la configuración global del sistema.

Métodos obligatorios:

getMinimumStock()

updateMinimumStock(int newStock)

Actualiza el valor en memoria

Persiste el nuevo valor en MongoDB

Vista (View – Interfaz Gráfica Simulada)

Crear una clase dentro del paquete View.

La Vista NO puede acceder directamente a MongoDB ni al Singleton AlarmConfig.

Responsabilidades:

Mostrar una alerta de stock bajo (JOptionPane o consola simulada).

Mensajes EN INGLÉS.

Datos a mostrar: Product ID, Product Name, Current Stock.

Simular una interfaz de configuración:

Campo de texto para ingresar un nuevo valor de minimumStock.

Botón "Update".

La Vista captura el input del usuario y delega la acción al Controlador.

Controlador (Controller – Lógica de Negocio)

Crear una clase dentro del paquete Controller.

Responsabilidades:

Consultar la colección products en MongoDB.

Iterar todos los productos.

Regla de negocio:
if (product.stock <= AlarmConfig.minimumStock)
→ mostrar alerta en la Vista

Gestión de eventos:

Recibir el nuevo valor de minimumStock desde la Vista.

Invocar AlarmConfig.updateMinimumStock(...).

El Controlador es el ÚNICO intermediario entre Vista, Modelo y Configuración.

Restricciones de Arquitectura (MVC ESTRICTO)

PROHIBIDO usar capas adicionales (Service, Repository, DAO, etc.).

PROHIBIDO que la Vista acceda al Singleton o a MongoDB.

PROHIBIDO que el Modelo contenga lógica de negocio.

SOLO se permiten los paquetes: Model, View, Controller y Config.

Modelo (Model)

Crear una clase Product que represente un documento de la colección products.

Contener únicamente atributos, constructores y getters.

Sin lógica de negocio.

Tecnologías Obligatorias

Lenguaje: Java

Build Tool: Maven

Base de Datos: MongoDB

Driver: mongodb-driver-sync

Arquitectura: MVC puro

Código limpio, legible y bien organizado.

OBJETIVO FINAL
Implementar un módulo de alertas de stock robusto, desacoplado y mantenible, alineado con patrones de diseño profesionales y arquitectura limpia, listo para escalar en un sistema real de ventas.
